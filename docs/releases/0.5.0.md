# v0.5.0 — Composable chats and conditional reply hints

Structured chats can now call other self-contained chats, return typed results,
and resume their caller without mixing transcripts or accepted answers.
Applications can issue messages with conditional reply hints bound to a specific
tool or chat branch. Declining an offered flow keeps the user in the caller.

## Highlights

- **Composable chats:** typed input and output, `Chat.branch`, nested call and
  return, suspension, resumption, and cancellation. The same definition can run
  independently or as a child. Effect services and errors propagate through the
  declared call tree.
- **Application-authored messages:** `Message.define`, `Message.hint`,
  `Message.emit`, `Chat.start`, and `Chat.post`. Text and hints persist atomically;
  retrying a message identity replays it without rearming its hints. Hints bind
  application-owned arguments to either a tool or a branch and expire after the
  owning invocation's next successfully committed reply.
- **Repeatable command conversations:** `Stage.interact` combines queries and
  commands with explicitly named completion tools. `Tool.acceptedAnswer` and
  `Tool.Context` expose validated collection results to application code.
- **Model profiles:** stages can select named `Model.profile(...)` services,
  including matching OpenAI-compatible layers, with explicit Effect requirements.
- **Client integrations:** React-free `/client` factories cover ordinary turns,
  debug turns, and explorations. `/assistant-ui/react` adds
  `StructuredChatAssistantProvider` with an optional lazy debug window.
- **Presentation and inspection:** composed replies identify the invocation that
  produced them. Browser answer snapshots remain invocation-local; debug capture
  includes routing and stage model calls. Root explorations retain root context
  while a child is active.

## Breaking changes and upgrade notes

### D1 session expiry

Expired sessions now retain terminal identity tombstones and load as
`Session.Expired`. Reusing an expired identity no longer starts a new session;
applications must allocate a new session ID.

The D1 session table now includes `lifecycle` and `expired_at`, permits null
snapshot columns for expired rows, and constrains active and expired row shapes.
New databases can use the bundled schema. Existing D1 installations must migrate
their table to that schema before deploying this version: rerunning the bundled
`CREATE TABLE IF NOT EXISTS` statement does not upgrade an existing table.

### Command identities

`Tool.deriveCommandId` no longer accepts a `command` field. A command ID identifies
the whole persisted turn, including when routing enters a child chat. Application
receipt stores must share an identity namespace across commands and reject a
retry that changes the command name or arguments. This preserves the same ID
when a command succeeds but the enclosing session write must be retried.

### Optional assistant-ui peers

The optional `@assistant-ui/core` peer now requires `^0.3.15`; the new React
provider entry uses optional `@assistant-ui/react` `^0.15.16`. The React-free
client entry can be imported without React or assistant-ui installed.

## Fixes

- Unified query, command, interaction, and repair dispatch through a compiled
  registry while preserving transformed inputs and application Effect types.
- Kept accepted-answer context current during collection, repair, guards,
  validation, and exploration, including transformed values after persistence.
- Protected D1 expiry against concurrent refreshes using both revision and
  timestamp checks, and counted each bulk-cleanup expiry once.

## Validation

The release passed lint, architecture checks, TypeScript checks, 344 Bun tests,
the Cloudflare worker test, package type checks, Node ESM and React-free client
smoke tests, and package-content validation. Routing behavior was verified with
scripted models; natural-language routing should also be evaluated with the
application's chosen provider.
